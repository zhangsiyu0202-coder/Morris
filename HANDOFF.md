## Mental model — Instruction (unchanged, still binding)

**Definition**: Instruction is the **AI moderator's complete operating manual**
for a study — CLAUDE.md for the interview. Not "research background", not a
"persona field". Study-scoped, single free-form markdown, multi-consumer /
single-source, derived from the researcher's questions, hand-editable but not
gated. See ADR-0015 for the full boundary rules (they did not change this
session).

**Single research-intent source of truth (Wave 4 made this real)**: every
downstream LLM consumer now reads the same string via
`resolveResearchIntent(...)` — prefer `Survey.instruction`, fall back to the
composed four legacy fields. No consumer composes its own subset anymore.

## Wave 3 detail (committed `7994c81`)

`apps/web/lib/assistant/tools/create-study-draft.ts`:

- `withBaselineInstruction(draft)` — when `draft.instruction` is empty, flattens
  the drafted questions and calls the SAME shared `generateInstructionBaseline`
  as the guide-editor button (prompt not forked), injecting the result before
  `createSurveyFromDraft`. Skipped when Morris already supplied an instruction.
- **Signed-in persist path only.** The anonymous preview path is untouched so it
  stays a lossless echo of the parsed draft (guards the `P-MORRIS-CSD` property)
  and never spends an LLM call for an unauthenticated caller.
- **Best-effort**: `instruction` is optional (composer + Wave 4 consumers fall
  back to legacy fields), so a generator failure logs a warn
  (`morris.tool.createStudyDraft`) and persists with an empty instruction rather
  than failing study creation.
- Tests: 4 new; `fakeInstructionGeneratorModule` added to `install-mocks`.

Design note (why signed-in only): the alternative — generating in the anonymous
preview too — would break `P-MORRIS-CSD` (anonymous preview echoes
`SurveyDraftSchema.parse(input)` losslessly) and force LLM mocking across its 50
property runs, for an artifact that is never persisted. The ADR's two-step
generation targets the *persisted* study, so signed-in-only is compliant.

## Gotchas / knowledge that must survive

1. **Contract package builds to `dist/`**: after editing `packages/contracts/src/*`,
   run `pnpm -F @merism/contracts build` before app-level typecheck sees the change.
   If typecheck says a new export doesn't exist — you forgot to build contracts.

2. **`resolveResearchIntent` is the single research-intent path.** Do NOT
   re-compose legacy fields anywhere else. New LLM consumers that need "what is
   this study about" call `resolveResearchIntent(...)`. `composeInstructionFromLegacy`
   returning `null` is only for UI button-gating (web re-export); analysis
   callers use `resolveResearchIntent` which coerces `null` → `""`.

3. **Appwrite schema apply is non-destructive by default**: `pnpm schema:apply`
   adds columns but never drops. Wave 5 will need an `--allow-destructive` flag —
   not implemented yet; check `packages/appwrite-schema/src/apply-schema.ts`
   before starting Wave 5.

4. **Baseline generator prompt is NOT forked.** Both the guide-editor button
   (Wave 2) and Morris `createStudyDraft` (Wave 3) call the one
   `generateInstructionBaseline` in `apps/web/lib/instruction/generator.ts`. Any
   prompt change happens there, once.

5. **DeepSeek for Morris/web-side, Qwen for the interview worker.** The baseline
   generator uses DeepSeek because it runs web-side. Do not introduce Qwen there
   unless an ADR changes it.

6. **Legacy 4-pack still written on new rows.** `apps/web/lib/actions/survey.ts::saveSurveyDraft`
   still writes `moderatorInstruction` + `flowConfig.{researchGoal,targetAudience,introScript}`,
   and `SurveyDraftSchema` still requires them non-empty. Intentional during the
   deprecation cycle; Wave 5 changes this.

7. **`getServerClient().databases`, not `.db`** on the web side (Function-side is
   sometimes `.db`). Grep an existing action if unsure.

8. **LSP was unavailable this session** (`find_references` failed: "No language
   server configured for typescript"). Consumer enumeration used `grep`. If you
   rely on `find_references`, verify the LSP is up first.
